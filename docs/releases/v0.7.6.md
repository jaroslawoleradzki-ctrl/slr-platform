# SLR Platform v0.7.6 — Workflow Status Propagation and Refresh Performance

**Release date:** 2026-10-29
**Base version:** v0.7.5
**Breaking changes:** None intended
**Production deployment:** Not performed as part of this release

## Summary

v0.7.6 closes the post-deployment gap found in v0.7.5 (BUG-01): approving or rejecting an
import updated the Sources row, but the shared workflow status used by the sidebar and
dashboard stayed stale until a full refresh completed. The refresh itself fanned out ten
endpoints and waited for the slowest one (~2.3 s on production data).

The decision is now applied to the shared `workflowStatus` immediately, and the refresh
publishes partial results as each endpoint settles. Read models for duplicate groups and
PRISMA metrics use a short-lived, per-project memoization cache with explicit invalidation.

No research data, PRISMA semantics, deduplication logic, API response shape, or database
schema changed. No migrations.

## 1. Prompt decision propagation

- `ProjectContext.applyImportReviewDecision` updates the active project's import
  effective/review status and recomputes `workflowStatus.sources` immediately.
- The Sources stage becomes `completed` when no import remains `warning`; the import count
  is intentionally unchanged.
- `SourcesIngestionPage` applies the decision result to the matching import-history row and
  updates the affected source-summary successful/warning counters.
- Sidebar items expose `data-stage-state`; dashboard cards expose `data-state` so the
  behavior is asserted in E2E instead of inferred from text.

## 2. Incremental workflow refresh

- `refreshWorkflowStatus` resolves each endpoint independently and merges partial results
  into `workflowStatus` as they settle.
- Each endpoint has an 8 s timeout via `Promise.race`; a failed or timed-out endpoint
  degrades to a partial status instead of blocking the whole read model.
- Per-stage loading state (`workflowStatusLoadingStages`) is exposed to the UI and rendered
  as per-stage indicators on the dashboard while the global banner remains.

## 3. Read-model memoization

- `getDuplicateGroups` and `getPrismaMetrics` are memoized for 10 s with in-flight
  deduplication.
- Cache keys are scoped as `${projectId}:dedup` and `${projectId}:prisma`.
- `setActiveProjectId` clears both the memo cache and in-flight requests on every project
  switch, preventing cross-project read-model reuse.
- Caches are invalidated on import, decision, normalization, and deduplication mutations.

## 4. Backend hot-path optimization

- `ExtractionEligibilityService.get_eligible_publications` previously called `get_input_set`
  once for the batch and again inside every `evaluate_publication`.
- `evaluate_publication` now accepts the already-computed input set from the batch path.
  Semantics, counts, and API shapes are unchanged.

## 6. Known limitations

- **Production timing NOT VERIFIED.** The project owner waived the production measurement
  gate on 2026-10-29. The hot-path change removes a confirmed redundant call and local
  measurements are in the millisecond range, but no before/after production figure is
  claimed.
- The timeout path is covered indirectly (partial-result tests), not with fake timers.
- The performance test uses large mocked arrays; it validates frontend computation and
  render, not network/backend latency.
- Reviewer identity remains a self-asserted workflow identifier (unchanged from v0.7.5).

## 7. Research integrity

- No PRISMA stage populations, canonical publications, source records, working-collection
  totals, duplicate decisions, or screening decisions are modified by decision propagation
  or refresh.
- Import decisions remain non-destructive, append-only, and attributed.
- No scientific decision is automated.

## 8. Rollback

- v0.7.6 adds no migrations and no schema changes, so rollback is image-only.
- Restore the previous container (`slr-platform:v0.7.5`) and keep the pre-deployment
  database backup available; do not run destructive SQL.
- See `docs/reviews/V076_RELEASE_REPORT.md` for the full release evidence and deployment
  preflight.
