# SLR Platform v0.7.1 — Corpus Pipeline Integrity

**Release date:** 2026-09-23
**Base version:** v0.7.0
**Breaking changes:** None

## Summary

v0.7.1 closes a data-integrity leak in which Normalization and Deduplication
operated over the full working collection, including records removed during
Pre-Screening review. The release introduces an authoritative Active Corpus
boundary, a durable pre-screening archive, corrected PRISMA stage separation,
and a controlled physical reconciliation mechanism. The integrated
implementation passed independent final review and post-integration
verification on `development` before release preparation.

## Authoritative Active Corpus Boundary

- A single source of truth defines the active project corpus: persisted rows
  that are not superseded by duplicate merges, not removed during
  Pre-Screening, and not physically archived.
- Normalization, Deduplication, screening input, exports, and integrity audit
  consume exactly this corpus — no stage maintains an independent
  full-collection data path.
- Provider provenance (Crossref, OpenAlex, Semantic Scholar, file imports) is
  treated uniformly; no provider-specific filtering exists in the pipeline.

## Pre-Screening Archive Foundation

- Records removed during Import Review are preserved with title, authors,
  identifiers, DOI, provenance, full document snapshot, removal reason, and
  audit metadata in the durable `pre_screening_archive` registry.
- Retrieval history (`import_history`) is never mutated by archival.
- Legacy projects without pre-screening decisions remain fully compatible.

## Normalization on Active Corpus

- Normalization processes exactly the Active Corpus; reruns cannot resurrect
  removed records and never rewrite or delete non-active rows.
- Reported processed/clean counts describe records actually processed.

## Deduplication on Active Corpus

- Duplicate candidate generation, groups, and merges involve only active
  records; removed records can never become group members.
- Cross-provider duplicates among retained records continue to be detected.
- Stale merges/decisions from previously unfiltered runs have a deterministic,
  idempotent reconciliation path that preserves legitimate merge history.

## Corrected PRISMA Accounting Separation

- Identification (retrieval history), corpus-preparation removals, active
  pipeline populations, and formal screening are reported as distinct stages.
- Pre-screening removals never inflate formal screening counts or exclusions.

## Controlled Physical Reconciliation Mechanism

- A transactional archive-and-remove service with dry-run preflight
  assertions, idempotent fingerprints, and a run ledger is included.
- Production reconciliation is NOT automatically executed by this release; it
  remains a separate controlled operation with its own backup and approval.

## Legacy / Migration Compatibility

- Migration `0032` creates the archive schema; migration `0033` supports the
  reconciliation ledger. Both apply cleanly to fresh and existing databases.
- Existing derived state (normalization executions, duplicate decisions and
  merges) reconciles deterministically without silent data loss.
