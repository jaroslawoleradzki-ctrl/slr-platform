# SLR Platform v0.7.3 — Import Integrity, Duplicate Safety and Performance

**Release date:** 2026-10-27
**Base version:** v0.7.2
**Breaking changes:** None intended
**Production deployment:** Not performed as part of this release

## Summary

v0.7.3 completes the R1–R5 remediation of the import, duplicate-review, recovery,
and PRISMA paths. It preserves every file-imported source occurrence, makes
canonical linking auditable, resolves post-merge DOI re-imports to the active
canonical publication, and removes the severe duplicate-group/PRISMA
performance regression identified by the independent final audit.

All duplicate decisions remain researcher-controlled. No automatic title-based
merging is introduced. The historical 508-source/62-row RIS discrepancy is
**not** claimed as resolved by this release.

## 1. RIS/BibTeX import integrity

- File imports persist a source record for every source occurrence.
- Exact DOI links, repeated occurrences, title candidates, invalid-DOI records,
  and repository-skipped rows are distinguished in durable audit tables.
- A repository that declines an insert is recorded explicitly instead of being
  reported as imported.
- Failed-import diagnostics survive later successful imports and remain
  inspectable through the import history and source-record endpoints.

## 2. Source-record provenance and auditability

- Each source record retains original DOI text, normalized DOI, DOI status,
  record fingerprint, source file identity, bibliographic metadata, canonical
  publication link, match type/reason, and recovery status.
- Candidate-group snapshots preserve the group a source record belonged to even
  after later review or merge operations.
- Provider imports record their provider-specific source identity alongside the
  canonical link.

## 3. Duplicate review and canonical DOI handling

- Duplicate candidates are generated conservatively and always require a
  human decision; nothing is merged automatically.
- A DOI that matches a superseded publication is resolved through the
  `superseded_by` chain to the active canonical publication.
- One-step chains, multi-step chains, missing targets, malformed cycles,
  conflicting DOI evidence, and cross-project isolation are handled
  deterministically.
- Dangling or cyclic chains raise an explicit safe error and roll back the
  import; no source occurrence is silently linked to an invalid target.
- Existing merge decisions and historical source rows are not rewritten.

## 4. Recovery and reconciliation safeguards

- Recovery requires an explicit reviewer approval with rationale and timestamp.
- Recovery into one project cannot affect another project.
- Duplicate-group decisions and merges fully contained in the Active Corpus are
  preserved; stale records outside it have a deterministic reconciliation path.
- Failed imports and skipped rows are auditable rather than silently discarded.

## 5. PRISMA source-aware accounting

PRISMA now distinguishes, consistently across API and exports:

- source records and repeated source occurrences;
- exact DOI duplicates;
- canonical publications;
- merged records;
- recovered records;
- pending duplicate groups;
- historical projects without source rows (explicit historical fallback).

The reported counts are derived from persisted source state rather than
inferred import totals.

## 6. Duplicate-group and PRISMA performance improvements

- Normalized titles are computed once per build.
- Candidate generation uses exact-title buckets, token-count guards,
  digit-masked shape keys, a top-5 rarest-token inverted index, a short-title
  bucket, and component-aware skipping.
- Character similarity uses an exact prefix/suffix/multiset upper bound before
  the full `SequenceMatcher` ratio.
- Union-find operates on dense integer indexes instead of UUIDs.
- PRISMA reuses one screening input set for workflow status and excluded counts,
  reducing duplicate-group builds from three to two per request; the
  duplicate-groups endpoint performs one build per request.
- No record-count cap or silent candidate discard is used.

Measured on deterministic A–E fixtures with disposable SQLite:

| 2000 records | Before | After |
|---|---:|---:|
| Duplicate-groups service path | 38.124 s | 0.531 s |
| PRISMA | 79.233 s | 1.027 s |

Candidate output is identical to the pre-remediation implementation through
2000 records; 224,472 old/new similarity decisions were compared with zero
mismatches.

## 7. Regression tests and validation

- Backend: 2544 tests passed.
- Frontend: 342 tests passed across 44 files.
- TypeScript type-check and production build pass.
- Migration-focused suite: 31 tests passed.
- Targeted R1–R5 suite: 60 tests passed.
- Ruff and Mypy pass.
- GitHub Actions CI passed on the integration branch and on the release
  branches using the dedicated self-hosted AI-node runner.

## 8. Known limitations

- **Historical 508/62 RIS discrepancy: NOT VERIFIED and NOT resolved.** The
  original RIS files and source rows required to reproduce it are unavailable.
- The audit’s original 578-publication project cannot be replayed; performance
  figures use synthetic fixtures of the same scale.
- A worst-case 2000-title near-identical family remains slower than normal data
  because every pair is a legitimate candidate unless the numeric-only rule
  applies. No candidates are dropped.
- Production deployment, production migrations, and production data
  reconciliation are not part of this release.

## Compatibility and upgrade notes

- No API or export contract was intentionally removed.
- New migrations `0034`–`0037` add source-record, skip-audit, recovery-audit,
  and duplicate-candidate-snapshot tables.
- Existing projects remain readable; historical projects without source rows
  use the documented PRISMA fallback.
- Existing manual duplicate decisions and merge records are preserved.
