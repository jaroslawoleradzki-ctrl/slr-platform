# SLR Platform v0.6.4 — Semantic Scholar Unknown Language Filtering Fix

SLR Platform v0.6.4 is a focused hotfix for post-query language filtering of
Semantic Scholar results.

## Fixed

- Semantic Scholar records with an unknown language (`language=None`, the
  deliberate v0.6.3 mapping) are no longer incorrectly discarded when a
  language filter such as `["en"]` is active.
- The post-query execution constraints no longer treat an unknown language as
  a known non-match: a record without provider-supplied language evidence
  remains a candidate because Semantic Scholar cannot enforce the language
  filter on the physical query.
- Language is not inferred or fabricated from title, abstract, author data,
  venue, or any heuristic; missing data remains missing data.
- Records with known language values remain strictly filterable:
  - known match (e.g. `language="en"` with filter `["en"]`) is kept,
  - known non-match (e.g. `language="de"` with filter `["en"]`) is rejected.
- The existing Semantic Scholar language-filter warning now explicitly states
  that the language restriction could not be enforced for records with unknown
  language; `warnings` and `is_lossless` semantics are otherwise unchanged and
  the public API shape is untouched.
- Added regression coverage reproducing the production observation where
  `total_count=7574` was returned while every Semantic Scholar record was
  silently filtered out locally (`returned_count=0`).

## Compatibility and scope

- v0.6.2 provider-specific plain-text query rendering is unchanged.
- v0.6.3 removal of the unsupported `language` request/response field is unchanged.
- OpenAlex and Crossref behavior is unchanged.
- No retry/backoff or pagination changes beyond this defect.
- No database schema change or migration is required.
- No AI/LLM functionality is added.
