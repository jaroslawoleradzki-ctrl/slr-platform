# SLR Platform v0.6.6 — UI and Workflow Navigation Improvements

**Data wydania:** 2026-08-26  
**Wersja bazowa:** v0.6.5  
**Zakres:** UI / navigation improvements  
**Nie zawiera:** Search canonical Boolean / Crossref / Semantic Scholar / OpenAlex fixes (przygotowywane do v0.6.7)

---

## Podsumowanie

Release v0.6.6 skupia się na uporządkowaniu interfejsu użytkownika ekranu wyników wyszukiwania oraz nawigacji procesu SLR (lewy sidebar + górny pasek workflow). Celem było poprawienie czytelności, hierarchii informacji i spójności statusów bez zmiany logiki backendowej.

---

## Search Results UI (Problem A)

### Query Preview
- **Kolapsowalny podgląd zapytania** — domyślnie zwinięty, nie dominuje ekranu.
- Kanoniczne zapytanie Boolean w jednej linii z przyciskami **Rozwiń / Kopiuj**.
- Ostrzeżenia o niekompletnej adaptacji (`Dostosowano składnię/ograniczenia`) widoczne jako **chiipy** nawet w trybie zwiniętym.
- Pełne zapytania per-provider dostępne po rozwinieniu.

### Status pobierania providerów
- Prezentacja jako **strukturalna tabela**: `Provider | Status | Pobrano | Zgłoszono`.
- **Sześć stanów** z odrębnymi ikonami (nie tylko kolorem): `pending` ⏳, `running` ⟳, `complete` ✓, `partial` ⚠, `cancelled` ⊘, `failed` ✗.
- Flagi limitów API widoczne w wierszu providera.
- Sumy na dole: „Łącznie pobrano: X · Po lokalnych filtrach: Y”.

### Statystyki wyników
- Nowy **trzy-kartowy pas** statystyk: „Znaleziono w providerach”, „Pobrane rekordy”, „Wybrane do importu” — duża czcionka monospace, jasna hierarchia.
- Subtitle ekranu teraz pokazuje datę wykonania i listę providerów.

### Zaznaczanie i akcje
- Zgrupowane w obramowanym toolbarze:
  - Checkbox **„Zaznacz wszystkie widoczne rekordy (strona N)”**
  - Link **„Zaznacz wszystkie pobrane (N)” / „Odznacz wszystkie pobrane rekordy”**
  - Primary **„Importuj zaznaczone”**
  - Wyjaśnienie trzech zakresów: *widoczna strona* / *wszystkie pobrane* / *pełny zestaw providerów*.
- Przycisk **„Pobierz wszystkie dostępne”** z wyjaśnieniem różnicy między załadowanymi rekordami a zgłoszoną liczbą trafień.

### Paginacja lokalna
- Przeniesiona **bezpośrednio pod listę rekordów**, wizualnie powiązana (tło/border jak lista).
- Format: `← Poprzednia | Strona X z Y (rekordy A–B z C) | Następna →`.

## Workflow Navigation (Problem B)

### Lewy sidebar — spokojniejszy, czytelniejszy
- Numeracja w **stałych chipach** 1–9 (monospace, 20×20 px); aktywny etap = accent background + wypełniony chip.
- Zakończone etapy: zielony check + label („Skończono”, „Oceniono”, „OK”).
- Wymagające akcji: amber **Badge pill** z licznikiem („N do oceny”, „Wymaga konfiguracji”).
- Błędy: czerwony AlertCircle + label.
- Niedostępne / oczekujące: muted Clock + label.
- **Kolor tylko dla stanów akcji** (pending-action, error) — brak „dziewięciu alarmów”.

### Górny pasek workflow — zwarty overview
- 9 chipów: krótkie etykiety („Search”, „Sources”, „Normalize”, „Dedupe”, „Screening”, „QA”, „Extraction”, „Synthesis”, „Export”) + ikona stanu + opcjonalny licznik alertów (dedupe).
- Statusy **wyliczone z pojedynczego rejestru** (`WorkflowStages` config) — brak hardcode’ów dla Extraction/Synthesis/Exports.
- Evidence Synthesis wyliczane z upstreams: `extraction.completed ∨ exports.pending_action → in_progress`.
- QA link poprawiony na kanoniczny `/quality-assessment` (był redirect `/qa`).
- **Tooltipy** na każdym chipie: pełna nazwa + detail label + nazwa stanu.
- Dwie nawigacje nie konkurują: topbar = szybki overview, sidebar = nawigacja + szczegóły.

### Wspólny model prezentacji statusów
- `config/workflowStages.ts` — pojedynczy rejestr 9 etapów (nazwa, path, status key).
- `components/workflow/stageStatusPresentation.tsx` — mapowanie 7 stanów na **odrębne glify + kolory + label** (4+ unikalne glify → status nie opiera się wyłącznie na kolorze).
- Sidebar i topbar konsumują ten sam model.

## Wpływ na użytkownika

| Obszar | Poprawa |
|--------|---------|
| **Szybkie zrozumienie zapytania** | Query preview domyślnie zwinięty, warningi zawsze widoczne, kopiowanie jednym kliknięciem. |
| **Status providerów** | Tabela z ikonami pozwala na błyskawiczne odróżnienie: kto pobiera, kto skończył, kto częściowo, kto failed. |
| **Liczebność wyników** | Trzy kafelki statystyk dają natychmiastowy obraz: ile znaleziono / pobrano / wybrano. |
| **Zakres zaznaczania** | Użytkownik jednoznacznie rozumie różnicę między stroną / pobranymi / wszystkimi. |
| **Nawigacja procesu** | Sidebar spokojniejszy, topbar daje overview w ułamku sekundy, statusy spójne w obu miejscach. |
| **Responsywność** | Działa poprawnie na 1920 / 1440 / 1280 px bez horizontal scroll ani nakładania. |
