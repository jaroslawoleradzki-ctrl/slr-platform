# SLR Platform v0.7.5 — Import Review Decision Feedback and Counter Refresh

**Release date:** 2026-10-29
**Base version:** v0.7.4
**Breaking changes:** None intended
**Production deployment:** Not performed as part of this release

## Summary

v0.7.5 fixes the import warning decision feedback loop so a successful research decision
is never presented as pending, stale, or failed. The dialog closes as soon as the backend
confirms the decision, applies the server-returned effective status and review state, and
moves the Sources/workflow refresh to the background. A failed refresh is shown as a
refresh problem with a retry action instead of being reported as a failed decision.

Acceptance remains non-destructive: only the effective import status (`warning` →
`Zaimportowano`) and the warning-derived counters change. Working-collection, canonical,
source-record, and PRISMA populations are unchanged.

## 1. Decision dialog lifecycle

- `ImportReviewModal` consumes the decision response (`effective_status`, `review_status`,
  decision summary) as its terminal state, notifies the parent via `onDecisionApplied`, and
  closes immediately after a successful POST.
- The shared `saving` flag is replaced by a per-action `pendingAction` state. Only the
  action in flight shows a spinner; both decision triggers are disabled while pending;
  `Zamknij` is re-enabled when the request settles. Repeated activation submits at most
  one POST.
- Decision-request errors keep the dialog open with the backend message and structured
  blockers. Refresh errors do not reopen the dialog and are not rendered as decision
  failures.

## 2. Sources refresh

- `FileDropzone.onChanged` starts the Sources summary and workflow-status refreshes
  concurrently via `Promise.allSettled` without blocking dialog close.
- `SourcesIngestionPage` applies the decision result to the matching import-history row
  immediately, so the row shows `Zaimportowano` before any network refresh completes.
- A failed summary refresh renders a visible `role="alert"` banner with a `Ponów` retry
  action even when an older summary is still displayed.
- The summary loader depends on `activeProject.id` instead of the whole project object,
  removing redundant fetches caused by object-identity churn.

## 3. Counter and research-integrity invariants

- Acceptance changes only the effective import status and warning-derived counts
  (`successful_imports_count` +1, `warning_imports_count` −1 for the source).
- `records_added_count`, working-collection total, canonical-publication count,
  source-record count, skip-audit rows, duplicate/screening/QA/extraction/synthesis
  records, and PRISMA populations remain unchanged.
- Pinned by new service, API, and integration tests, plus a browser E2E test
  (`frontend/e2e/import-review.spec.ts`).

## 4. Backend and persistence

- No backend, API, schema, or migration change. The decision response already contained
  the required fields. Reverting the frontend restores the previous behavior without data
  repair.

## 5. Database migration

None. This is a frontend behavior, test, and documentation change.

- Upgrade path: deploy v0.7.5 frontend against the existing backend. No data repair.
- Rollback path: revert the frontend to v0.7.4; no database repair required.
