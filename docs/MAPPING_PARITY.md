# Canonical Mapping Parity

## Purpose and boundaries

This document defines the expected mapping boundary from search-provider responses to the canonical `Publication` model for OpenAlex, Crossref, and Semantic Scholar. It is the decision source for Harmonization Phases 5.2–5.5.

Mapping parity does not:

- define global normalization after records are merged;
- include deduplication, screening, or other review workflow behavior;
- require invented values when a provider does not supply a field;
- require providers to expose identical raw response structures;
- couple API clients to domain mapping;
- introduce new user-facing functionality.

## Field classes

### Required

A search result cannot become an auditable canonical publication without:

- `title`;
- `provenance.source`;
- `provenance.source_record_id`;
- `provenance.retrieved_at`;
- search context in provenance: `query_id`, `run_id`, and `rendered_query`.

A provider-native source identifier may also be represented as a canonical `Identifier` when the model and provider data allow it, but that does not replace `provenance.source_record_id`.

### Provider-data-dependent

These fields must be mapped when the provider response contains a valid value:

- abstract;
- authors, including display name, given name, family name, identifiers such as ORCID, and affiliations;
- publication year and date;
- publication identifiers, including DOI, PMID, and other stable provider identifiers;
- venue name, type, and identifiers such as ISSN;
- publisher;
- document type;
- language;
- URLs;
- keywords;
- open-access status.

Missing provider data produces `None` or an empty collection according to the domain model. Mappers must not fabricate values to create apparent parity.

### Deferred or generated canonical metadata

The following fields are outside provider mapping parity:

- `record_id`, `schema_version`, and `created_at` are generated by the canonical model;
- `title_normalized` belongs to the later global Normalization phase.

## Current-state matrix

Support values:

- **Yes** — currently mapped when valid provider data is present.
- **Partial** — some information is retained, but not in the complete canonical representation.
- **No** — not currently mapped.
- **Provider-dependent** — target behavior maps valid data when the provider supplies it.
- **Generated** — supplied by the canonical model.
- **Deferred** — intentionally outside Harmonization.

## Target Harmonization contract

- Every provider rejects a record without a valid non-blank title.
- Every publication returned from a search has complete source and search-context provenance.
- Every valid canonical field available in provider data is preserved.
- Missing, blank, malformed, or unsupported optional values become `None` or an empty collection.
- Missing or blank required values raise a clearly defined exception.
- Mappers never invent data to create apparent parity.
- Provider-native identifiers may remain provider-specific but use canonical `Identifier` objects.
- Provenance remains distinct from publication identifiers.
- Mapping is deterministic except for dynamic timestamps and generated UUIDs.
- Provider response order is preserved unless the canonical model explicitly deduplicates a collection.
- Identifier and boundary normalization rules are finalized in 5.3.
- Shared helpers are extracted only after real duplication is confirmed in 5.4.

## Explicit gap register

### 5.2 OpenAlex provider mapping parity — completed

The stable OpenAlex response structures now map available values for:

- abstract reconstruction;
- authorships, author display names, and author identifiers;
- institutions and affiliations;
- publication year and date;
- DOI and the OpenAlex work ID as a canonical identifier;
- primary location/source, venue name and type, and ISSN;
- work type to `DocumentType`;
- language;
- landing-page and related URLs;
- explicit open-access status.

Publisher remains unmapped because `host_organization_name` does not
unambiguously identify the publication publisher. Topics and concepts remain
unmapped because they are not necessarily publication-assigned canonical
keywords. PMID, structured given/family author names, and other unavailable
values remain provider-data-dependent gaps rather than invented data.

### 5.3 Cross-provider normalization consistency — completed

The provider boundary now applies this contract:

- strings are trimmed, blank optional strings are omitted, and non-strings are
  never coerced with `str()`;
- DOI values are lowercase and omit `doi:`, `doi.org`, and `dx.doi.org`
  HTTP/HTTPS prefixes;
- ORCID values omit HTTP/HTTPS `orcid.org` prefixes and a trailing slash, with
  a final `X` uppercased;
- ISSNs are trimmed, a final `X` is uppercased, and exact normalized duplicates
  are removed while preserving first-seen order;
- provider-native `OTHER` identifiers preserve casing and use `openalex` or
  `semantic_scholar` as their canonical source;
- URLs accept HTTP and HTTPS schemes case-insensitively, normalize only the
  scheme casing required by the canonical model, preserve the remainder, and
  retain first-seen order;
- language values are trimmed and passed to the canonical model, which applies
  lowercase and its existing minimum-length validation;
- known document and venue types map case-insensitively, unknown non-blank
  types use `OTHER`, and missing, blank, or non-string types remain `None`;
- authors retain provider order and casing; blank or malformed authors are
  omitted, and only Crossref-provided given/family fields are structured;
- years must be non-boolean integers from 1000 through 9999; full dates must be
  valid, may supply a missing year, and are dropped when they conflict with an
  explicit valid year;
- malformed optional values become `None` or empty collections without
  rejecting an otherwise valid record, except validation intentionally owned
  by the canonical model such as malformed non-blank language.

This is provider-boundary normalization only. It does not normalize titles,
resolve author or organization identities, merge records, deduplicate
publications, or implement the later global Normalization phase. Similar
normalization helpers are consolidated in Phase 5.4 only where their behavior
was confirmed identical.

### 5.4 Shared mapper utilities — completed

Provider-boundary rules with confirmed identical implementations now have one
source in `app/providers/search/mapping_utils.py`:

- trimming and rejecting blank/non-string values;
- DOI prefix and casing normalization;
- ORCID prefix, trailing-slash, and final-`X` normalization;
- ISSN trimming and final-`X` normalization;
- safe HTTP(S) URL boundary normalization.

Provider response structures remain local: OpenAlex inverted abstracts,
authorships and locations; Crossref HTML abstracts, `date-parts`, title and
author lists; Semantic Scholar publication types, external identifiers and
venues. Identifier ordering and deduplication also remain with the mapper that
owns each provider collection.

These utilities apply only at the provider → canonical mapping boundary. They
do not implement title normalization, global Normalization, entity resolution,
record merging, or deduplication.

## Harmonization completion criteria

Phase 5.5 is complete. The matrix is protected by both the machine-checked
capability specification and runtime mapping contracts in
`tests/unit/providers/test_cross_provider_mapping_contract.py`.

Runtime contracts verify title, abstract, authors, publication year/date, DOI,
venue name and ISSN, document type, language, URLs, optional defaults,
collection ordering, malformed optional values, and complete search provenance
for all three providers where those values are available.

Provider-data-dependent differences remain explicit: structured Crossref author
names and publisher, OpenAlex author identifiers and affiliations, Semantic
Scholar PMID and provider-native ID, and the intentionally different venue and
identifier coverage. Tests use separate provider fixtures and snapshots rather
than fabricating identical input or output fields.

Completed Harmonization guarantees:

- OpenAlex, Crossref, and Semantic Scholar meet the agreed canonical mapping quality;
- OpenAlex is no longer a title-only mapper;
- provider-boundary normalization rules are explicit and consistent;
- shared helpers cover only demonstrated duplication;
- cross-provider mapping contract tests protect the agreed behavior;
- provider-specific mapping tests remain separate;
- API clients remain separated from domain mappers.

Harmonization Phases 5.1–5.5 are complete.
