## 1. Executive Summary

v0.6.1 completes the final-output stage of SLR Platform. Today the application has:

- A **working, production-quality extraction-dataset export** (CSV + JSON, Phase 9.8) that is already wired end-to-end to the frontend.
- An **authoritative PRISMA funnel-metrics backend** (`PrismaMetricsService`) with correct post-canonical-merge semantics, rendered live in the frontend as an HTML/CSS flow diagram — but **no downloadable artifact** (SVG/PDF buttons are locked).
- **Import-only** RIS and BibTeX support (parsers + mappers are tested and stable); the corresponding **export directions do not exist** and are locked in the UI.
- **No XLSX capability at all** (no library in `pyproject.toml`); locked in the UI.

v0.6.1 must add: BibTeX export, RIS export, an XLSX research-matrix workbook, a deterministic PRISMA 2020 flow model exposed as JSON, server-side SVG rendering, server-side PDF rendering, real frontend download actions for all five formats plus PRISMA SVG/PDF, security hardening (formula-injection guards, filename sanitization), provenance metadata in exports, and a full test suite.

The plan is organized into **6 implementation slices**, ordered to minimize architectural rework: dataset foundation first, then format serializers, then the PRISMA render chain (model → SVG → PDF), then frontend wiring, then hardening/docs/E2E.

## 5. Export Dataset Semantics

### 5.1 One authoritative dataset layer

Introduce **`app/services/export_dataset_service.py`** — a single read-only query facade used by every v0.6.1 exporter:

```
ExportDatasetService
├── get_bibliographic_records(project_id) -> list[Publication]   # ACTIVE canonical records,
│                                                                 # ordered by position ASC, rowid ASC
│                                                                 # (= repository get_active_publications order)
├── get_extraction_read_models(...)      # thin delegate to ExtractionDatasetService (reuse, not duplication)
└── get_prisma_metrics(project_id, reviewer_id)  # thin delegate to PrismaMetricsService
```

Rules:

- **Single source of truth for "final publications" = `get_active_publications(project_id)`** (same ordering the Working Collection UI shows). Superseded duplicates can therefore never surface in any research export.
- All exporters are **read-only** (GET only; repositories invoked through read methods only).
- Extraction-derived sheets (XLSX) reuse `ExtractionDatasetService` read models so COMPLETE-filtering semantics stay identical between CSV/JSON and XLSX.

### 5.2 Per-format dataset binding

| Format | Dataset | Grain |
|---|---|---|
| BibTeX | Active canonical publications | 1 entry per publication |
| RIS | Active canonical publications | 1 record per publication |
| CSV (existing) | Extraction dataset (COMPLETE revisions) | publication / relationship rows |
| JSON (existing) | Extraction dataset (COMPLETE revisions) | read models |
| XLSX | Workbook (§11): Publications + persisted downstream stages | mixed grain, one sheet each |
| PRISMA SVG/PDF | `PrismaMetricsService` output | funnel counts |

### 5.3 Decisions requiring confirmation

- **OD-A → RESOLVED by D3 (ACCEPTED)**: the UI's "Zestawienie Rekordów CSV/JSON" cards REMAIN bound to the *extraction* dataset. No publication-bibliography CSV/JSON variant in v0.6.1; bibliographic need is served by BibTeX/RIS exports (§9, §10).

## 6. Proposed Architecture

```
                         ┌──────────────────────────────────────────────┐
                         │            ExportDatasetService              │   ← single read-only facade
                         │  (active pubs · extraction models · prisma)  │
                         └───────────────┬──────────────────────────────┘
                                         │
      ┌──────────────┬──────────────┬────┴───────┬─────────────────────────┐
      ▼              ▼              ▼            ▼                         ▼
 bibtex_writer   ris_writer   xlsx_workbook   PrismaFlowModel ──► svg_renderer ──► pdf_renderer
 (pure py)       (pure py)    (openpyxl)      (pydantic, layout-free)  (pure py)     (fpdf2)
      │              │              │            │                         │
      └──────────────┴──────┬───────┴────────────┴─────────────────────────┘
                            ▼
              NEW app/api/routers/exports.py
              GET /{pid}/exports/bibtex        → .bib   (application/x-bibtex)
              GET /{pid}/exports/ris           → .ris   (application/x-research-info-systems)
              GET /{pid}/exports/xlsx          → .xlsx  (SpreadsheetML, FileResponse/Response bytes)
              GET /{pid}/prisma/flow           → PrismaFlowModelDTO (JSON)
              GET /{pid}/prisma/flow.svg       → image/svg+xml
              GET /{pid}/prisma/flow.pdf       → application/pdf
```

Layering rules:

- Serializers are **pure functions** `(data) -> bytes/str`: trivially unit-testable, deterministic.
- Routers own HTTP concerns only: headers, filenames, error mapping (mirror `extraction.py` style).
- `PrismaFlowModel` is authoritative-shape output of `PrismaMetricsService` counts + static PRISMA 2020 stage definitions; SVG and PDF both render **from the model**, never from each other's pixels, and never re-count.

## 9. BibTeX Design

New module `app/services/export/bibtex_writer.py` (pure function `render_bibtex(publications) -> str`). No external dependency.

**Entry mapping** (inverse of `map_bibtex_record`):

| Field | Source | Notes |
|---|---|---|
| entry type | `document_type` inverse map (`JOURNAL_ARTICLE`→`article`, `CONFERENCE_PAPER`→`inproceedings`, `BOOK`→`book`, `BOOK_CHAPTER`→`incollection`, `DISSERTATION`→`phdthesis`, `REPORT`→`techreport`, else→`misc`) | fallback `misc` mirrors importer's `OTHER` fallback |
| citation key | see below | deterministic, collision-safe |
| title | `title` | braced `{...}`; inner braces doubled |
| author | authors joined `" and "`; each as `family_name, given_name` when both present else braced `{display_name}` | mirrors importer parse rules |
| year | `publication_year` | omit when None |
| journal / booktitle / publisher | `venue.name` (+ `publisher`) | `journal` for articles, `booktitle` otherwise (mirrors `_map_venue` precedence) |
| doi | identifier type DOI | omit when absent |
| url | first of `urls` | |
| abstract | `abstract` | omit when None |
| keywords | `keywords` joined `", "` | |
| language | `language` | |
| volume/number/pages | **absent from domain model** → omitted | flagged: importer also drops them today (Open Decision D5) |

**Citation key strategy (deterministic & collision-safe)**:

```
base  = f"{first_family_lower_ascii}{year}{first_title_word}"     # e.g. smith2021energy
key   = base                      if unique within export
key   = base + "-b", "-c", ...    assigned in ascending record_id (UUID str) sort order
```

Pure-ASCII transliteration of key characters (non-ASCII dropped); stability guaranteed because suffix assignment depends only on sorted `record_id`s, not insertion order.

**Escaping/Unicode**: emit UTF-8; brace-special-characters `{}` `%&#+~^_` inside values; double literal braces. Missing fields omitted entirely (never emitted empty). Superseded records excluded upstream (§5).

| DO | DOI identifier | importer normalizes via `normalize_doi` ✓ |
| UR | first URL | |
| AB | `abstract` | importer reads AB/N2 ✓ |
| KW (repeated) | one line per keyword | |
| LA | `language` | |
| N1 | none (no notes persisted) | |

## 11. XLSX Research-Matrix Design

**Meaning**: the UI copy promises *"Tabela syntezy z podziałem na etapy i statusy decyzji"* — a staged research matrix, **not** a flat publication dump.

**Dependency (architectural decision D1, flagged)**: add **`openpyxl>=3.1,<4.0`** (smallest mainstream write-capable xlsx lib; pure-Python wheel, Docker-safe, ~no transitive deps vs pandas/openpyxl alternatives). Alternative `xlsxwriter` rejected: write-only API complicates semantic test tooling less cleanly and is equally new.

**Workbook structure — only sheets backed by persisted models today:**

| Sheet | Rows | Columns (stable order) | Source |
|---|---|---|---|
| `Publications` | active canonical pubs | `record_id, position, title, authors(";"-joined), publication_year, doi, venue, document_type, language, keywords(";"), urls(";"), created_at` | `ExportDatasetService.get_bibliographic_records` |
| `Screening Title Abstract` | decisions on active pubs | `publication_id, reviewer/project outcome, outcome, decided_at` | screening decision repository read (latest-decision-wins semantics identical to PRISMA/workflow-status) |
| `Screening Full Text` | idem | idem | idem |
| `Quality Assessment` | assessed pubs | `publication_id, template/version, criteria profile columns…, completed_at` | QA repository (criterion-level profile, **no numeric collapse**) |
| `Data Extraction` | publication read models | canonical meta + per-template-field value/status columns (identical header scheme to extraction CSV) | `ExtractionDatasetService` |
| `Synthesis Relations` | approved analytical relations | `publication_id, group_item_id, source_practice, lean_category, source_effect, energy_category, direction, magnitude, evidence_character, approval_state` | synthesis matrix repo (same columns as snapshot CSV export) |
| `PRISMA Summary` | 1 row | all funnel metrics incl. `manual_source_breakdown` flattened | `PrismaMetricsService` |

Sheets whose stage has no persisted rows are still emitted with headers only (partial workflows stay readable).

**Rules**: fixed column order above; IDs always first-class string cells; null → empty cell (never `"N/A"` — matches phase-9.8 convention); multi-value → `"; "` join; row order = repository order (position ASC); **canonical filtering**: Publications sheet = active only; decision/extraction sheets naturally contain only active-pub IDs (downstream isolation guarantee, v0.5.7 §7). Excel-safe values: formula guard (§17) applied to every string cell; cell cap 32 767 chars → truncate + append marker `…[truncated]`.

### 12.1 D4 Verification Record — `studies_included_synthesis` ≡ final Full-Text INCLUDE population

**Decision D4 (ACCEPTED)**: `studies_included_synthesis` is DEFINED as the final Full-Text INCLUDE population. Verification performed 2026-08-24 against main @ `32f446d`.

Computation chain traced:

```
PrismaMetricsService.get_metrics()                          prisma_metrics_service.py:138
  └─ workflow.quality_assessment.eligible_count             project_workflow_status_service.py:169-172
       └─ ScreeningEligibilityAdapter.eligible_publications(   screening_eligibility_adapter.py:96-139
            project, FULL_TEXT → "quality_assessment", reviewer_id)
```

Two modes, both yielding exactly the FT-INCLUDE population:

1. **Multi-reviewer** (active Full-Text roster): `MultiReviewerScreeningService.project_outcome()` (`multi_reviewer_screening_service.py:199-212`) returns a FINAL outcome for AGREEMENT (unanimous) and RESOLVED (conflict-resolution verdict, incl. overridden outcomes via `record.resolution.resolved_outcome`). Eligibility requires `outcome.is_final AND outcome == INCLUDE`. Conflicts/stale/incomplete are excluded ⇒ "final" is honored.
2. **Single-reviewer** (no roster): the reviewer's **latest** FULL_TEXT decision must be INCLUDE (`screening_eligibility_adapter.py:126-137`, latest-wins identical to `records_screened_*`). Reviewer-scoped, consistent with the other PRISMA screening metrics.

Both paths iterate `input_set.publications` from `ScreeningInputService` = active canonical records (`get_active_publications`) ⇒ superseded duplicates structurally excluded.

**Verdict**: current value ≡ D4 definition in both modes; the docstring at `prisma_metrics_service.py:57-60` already states this exact definition ("final INCLUDE outcome at the Full-Text stage"). The field name `quality_assessment.eligible_count` merely names the downstream consumer of that set ("publications eligible to enter QA") and does not alter semantics. **No metric change required.**

v0.6.1 follow-ups derived from this verification:
- Docstring precision (P1, doc-only): state the two-mode rule + reviewer-scoping explicitly.
- Definition-locking tests (Slice 3/6): multi-reviewer resolved-conflict→INCLUDE counted; superseded record excluded; single-reviewer latest-decision-wins.
- Flow-model node label (§13): "Studies included" annotated per D4 wording.

**Side observation (out of scope, P2 known-issue)**: `QualityAssessmentExecutionService._get_eligible_publication_ids()` (`quality_assessment_execution_service.py:192-217`) is NOT roster-aware — it reads raw per-reviewer decisions directly. In multi-reviewer projects with an active FT roster and resolved conflicts, the QA *page* eligible list may diverge from PRISMA's `studies_included_synthesis`. This affects the QA screen only — not PRISMA, not exports. Flagged for a future QA-alignment release; v0.6.1 does not touch it (no QA redesign in scope).

## 13. PRISMA 2020 Output Model (Flow Model)

Three strictly separated layers:

```python
# app/domain/prisma_flow.py  (new)
class PrismaFlowNode(BaseModel):        # B: presentation-neutral model
    node_id: str                        # e.g. "identification.providers"
    stage: Literal["identification","screening_tasft","included"]  # PRISMA band
    label_key: str                      # i18n-stable key
    values: dict[str, int]              # e.g. {"count": 12}
    annotations: dict[str, str]         # e.g. manual-source breakdown lines
class PrismaFlowEdge(BaseModel):
    from_node: str; to_node: str
class PrismaFlowModel(BaseModel):
    project_id: str
    metadata: PrismaFlowMetadata       # §16
    nodes: list[PrismaFlowNode]        # deterministic order
    edges: list[PrismaFlowEdge]
    removed: dict[str, int]            # side-boxes: duplicates_removed, excluded_*
```

- **A (authoritative)** = `PrismaMetricsService` output — unchanged.
- **B (this model)** = pure transformation `build_flow_model(metrics, project_meta) -> PrismaFlowModel`; adds derived display figures (`duplicates_removed`, `excluded_* = screened − advanced` where derivable) and PRISMA 2020 band structure. Zero persistence, zero coordinates.
- **C (renders)** = SVG/PDF generators consuming B; frontend may later consume B via `GET .../prisma/flow` (its existing HTML chart stays authoritative for now — no rewrite mandated).

Partially completed reviews: nodes with zero counts still render (value `0`), side-box exclusions render only when their denominator > 0 — matching the metrics service' "later stages return zeros" philosophy.

## 14. SVG / PDF Architecture

**SVG — server-side, stdlib-only** (`app/services/export/prisma_svg_renderer.py`):

- Deterministic layout table: fixed node sizes/columns/bands keyed by `stage`; pure function `render_svg(model) -> str`.
- All text XML-escaped; `font-family` generic stack; A4-portrait-ish viewBox; printable standalone (`<?xml?>` header).
- Reproducibility: no timestamps inside SVG (metadata lives in the JSON model/filename instead), stable attribute ordering → byte-identical output for identical input (test-enforced).
- No browser screenshot, no headless engine, no AI.

**PDF — from the shared flow model, not from SVG pixels**:

Recommended pipeline: `metrics → PrismaFlowModel → fpdf2 vector drawing` (rects/lines/text share the same layout table as SVG via one small layout module).

- **Dependency (architectural decision D2, flagged)**: **`fpdf2>=2.8,<3.0`** — pure-Python, no system libs (unlike WeasyPrint/Pango/cairo), tiny Docker footprint, TTF embedding for Polish diacritics (bundle DejaVuSans or similar OFL font in repo).
- Alternatives rejected: `reportlab` (heavier, licensing considerations), `svglib` (adds XML-parse indirection without removing any dep), WeasyPrint (native GTK/Pango deps — worst Docker fit).
- Operational impact: two pure-python wheels added; Docker image size +~2 MB; no new OS packages; fonts shipped in-repo (`assets/fonts/`) so builds stay hermetic.

## 17. Security / Data-Safety Considerations

| Risk | Mitigation (v0.6.1) |
|---|---|
| CSV/XLSX formula injection (`=`/`+`/`-`/`@`/TAB/CR lead chars from malicious titles) | Neutralization prefix `'` in CSV serializer + XLSX cell writer (shared util `sanitize_cell`) |
| Filename injection | Filenames derive from `project_id` (UUID) + fixed literals only; never project title/user input |
| Malformed metadata (control chars, huge strings) | Strip `\x00-\x08\x0B\x0C\x0E-\x1F` in writers; XLSX 32 767-char truncation marker; SVG/PDF text escaped/clamped |
| XML attacks in SVG | stdlib `xml.sax.saxutils.escape` for every dynamic string; no DTD/entities emitted |
| Unicode edge cases (RTL override, zero-width) | Passed through verbatim in data files (research integrity > sanitization of scholarly strings) except control chars; noted in docs |
| Empty projects | All exporters return valid empty artifacts (headers-only CSV/XLSX, empty-list JSON, zero-filled PRISMA diagram, empty .bib/.ris) — never 500 |
| Partially completed workflows | Explicitly supported: zeros/header-only sheets (matches metrics-service philosophy) |
| Superseded publications | Structurally impossible in exports (§5 single boundary) + dedicated regression test |
| Mutation risk | Endpoints are GET-only; services receive read-method repos only; CI grep-style test asserts no write-repo call sites in export modules |
