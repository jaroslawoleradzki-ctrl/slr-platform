## Diagnosis being addressed

`v0.6.9-WP1-crossref-retrieval-quality-diagnosis.md` (§6–§10, §12D, §13, §15–§16):

- Missing Crossref abstracts turn candidates into `INDETERMINATE` (25/25 sampled missing-abstract records), and recall-first retention admits them into the same population as `MATCH` — including 0/3-evidence records such as the two irrelevant medical case studies.
- Group-evidence table for 27 retained records: 3/3 MATCH ×3; INDETERMINATE split 0/3 ×3, 1/3 ×4, 2/3 ×17.
- The validator itself is defect-free; the retention policy is intentionally recall-protecting. A hard evidence gate that silently deletes weak records is explicitly **not** recommended without measurement.
- Recommended WP4: compare current retention with a separate uncertainty tier before approving exclusions ("two-tier uncertainty handling — YES after measurement").

## Architecture investigation

Inspected before coding: `canonical_query_validator` (`CanonicalValidationResult(status, matched_terms, missing_fields)`, `evaluate_expression`, three-valued AND/OR/NOT), `FetchAllSearchService` retention loop (`NON_MATCH` rejected; `MATCH`/`INDETERMINATE` kept subject to `matches_execution_constraints`), `Publication`/result models, screening input flow (FetchAll merged results → snapshots → screening population; untouched), MATCH/NON_MATCH/INDETERMINATE counters, API DTOs and Fetch All progress frontend (no changes needed — experiment is backend-only).

Key finding: per-group evidence is obtainable by evaluating each top-level AND child with the existing `evaluate_expression` — an `INDETERMINATE` overall verdict implies zero `NON_MATCH` groups, so "evidenced groups" (group status `MATCH`) is well-defined and generic over any group count. No validation logic needs duplicating.

## Alternatives considered

- Threshold gate deleting 0/3 records in production: rejected — forbidden by the diagnosis without a labeled recall study and by WP4 safety rules.
- Reusing WP2 replay types directly: rejected — WP2 is unmerged and must not be depended upon; instead a plain-dict adapter boundary.
- Hard-coding Lean/Energy terms or 3-group logic: rejected — engine derives everything from status, group counts, and missing fields.
- API/frontend uncertainty queue now: rejected — priority is domain model + evaluator + tests; a future WP can expose it.

## Experimental uncertainty model

Single new pure module `app/services/uncertainty_experiment.py` (frozen pydantic, no I/O, never imported by production paths):

- `UncertaintyTier`: `MATCH` / `UNCERTAIN_STRONG` / `UNCERTAIN_WEAK` / `UNCERTAIN_NO_EVIDENCE` / `NON_MATCH` — kept strictly separate from canonical status.
- `UncertaintyCandidate`: domain-level input (`candidate_id`, `canonical_status`, `positive_group_count`, `evidenced_group_count`, `missing_fields`, `abstract_missing`, `group_statuses`) with consistency validation (MATCH ⇒ K==N; INDETERMINATE ⇒ K<N; K≤N).
- Tier rule (generic): INDETERMINATE with K==0 → `NO_EVIDENCE`; K==N−1 → `STRONG` (all but one group evidenced); otherwise `WEAK`.
- `classify_candidate(query, publication, candidate_id)` validates with the real validator and derives groups/evidence/missing fields — the only production logic touched, read-only.
- `candidate_from_evidence_dict` — documented plain-JSON adapter (unknown keys ignored) forming the WP2 integration boundary.

## Policy scenarios

`assign_population` is a total function (every candidate lands in exactly one of `MAIN` / `UNCERTAINTY` / `REJECTED`):

- `CURRENT_RECALL_FIRST`: MATCH+INDETERMINATE → MAIN; NON_MATCH → REJECTED (reproduces current behavior).
- `SEPARATE_ALL_UNCERTAIN`: MATCH → MAIN; all INDETERMINATE → UNCERTAINTY; NON_MATCH → REJECTED. Nothing deleted.
- `EVIDENCE_TIERED_UNCERTAIN`: as above, with uncertainty split measurably by tier (STRONG/WEAK/NO_EVIDENCE counts). Nothing deleted.
- `SEPARATE_UNEVIDENCED_ONLY` (extra scenario): only 0-evidence uncertainty moves out; STRONG/WEAK stay in MAIN. Nothing deleted.

## Experimental output

`run_experiment(classified, scenarios)` returns totals (total/MATCH/NON_MATCH/INDETERMINATE), INDETERMINATE evidence distribution by K, missing-fields distribution, missing-abstract count, and per-policy main/uncertainty (by tier)/rejected counts plus `discarded_uncertain_count` — computed honestly and zero for every built-in policy — with per-candidate assignment rows for later inspection. Input order preserved; aggregates order-independent; models frozen and JSON-serializable.

## Example comparison

Deterministic neutral-term fixture (3 groups; explicitly not a population claim): 1 MATCH, 1 NON_MATCH, 0/3 + 1/3 + 2/3 INDETERMINATE (all missing abstracts):

| Scenario | Main | Uncertainty (S/W/N) | Rejected | Discarded |
|---|---|---|---|---|
| CURRENT_RECALL_FIRST | 4 | 0 | 1 | 0 |

## Known limitations

- Tiers are analytical lenses, not validated relevance judgments; STRONG/WEAK cut (K==N−1) is a transparent convention, not an empirically tuned threshold.
- Fixtures are neutral-term mocks, not a population sample; numbers must not be quoted as real-world rates.
- No persistence or UI exposure yet — by design, for a future WP.

## Methodological implications

- MATCH and INDETERMINATE can now be analyzed separately, and 0/N uncertainty is directly measurable — the two capabilities the diagnosis required before any policy decision.
- The experiment confirms the diagnosis framing: under SEPARATE_ALL_UNCERTAIN the entire screening-volume question reduces to the measurable INDETERMINATE-by-evidence distribution, with zero recall risk since nothing is discarded.
- Any future exclusion proposal must still pass the labeled-recall-study bar the diagnosis sets; this WP provides the measurement harness for it.

## Recommendation for future UI/policy work

Expose the uncertainty queue read-only first (counts by tier + candidate rows via the frozen result models, which already serialize to JSON), keep recall-first as the default retention path, and run the tiered comparison against WP2 replay data from a real run before proposing any exclusion. Do not promote `SEPARATE_UNEVIDENCED_ONLY` (or any variant) to production without that labeled study.
