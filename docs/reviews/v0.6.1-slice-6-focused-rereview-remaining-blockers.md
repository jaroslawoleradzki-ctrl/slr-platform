### P1-S6-4 — SVG width fitting underestimates wide glyphs

- Severity: P1
- Exact file/function/document:
  - `app/services/export/prisma_svg_renderer.py`, `_measure_svg_text_width`
  - `app/services/export/prisma_svg_renderer.py`, `_fit_text_svg`
  - `app/services/export/prisma_svg_renderer.py`, `render_prisma_svg`
  - `tests/unit/services/test_exports_hardening.py`, `TestPrismaDiagramHardening.test_svg_width_aware_fitting_with_wide_glyphs`
- Concrete evidence: For `"W" * 150`, `_fit_text_svg(..., 820, 11)` produces a 78-character fitted string measured by its own estimator as `811.25`, while the bundled DejaVu Sans metrics measure that output as `848.683`. Positioned at `x=20`, it extends to approximately `868.683`, outside the 860-wide viewport. The protocol case is estimated as `539.66` but measures `563.409`, exceeding its 550-wide allocation.
- Actual current behavior: The SVG fitter is glyph-sensitive but not conservatively width-safe. Wide titles can still overflow. The regression test validates production's estimator using that same estimator, so it passes despite the overflow. The PDF implementation uses actual font metrics and does not exhibit this specific defect.
- Required behavior: Fitted SVG title and protocol text must remain within their allocated regions under independent rendered-font measurement.
- Consequence: Project or protocol identification can be clipped in a required research artifact.
- Smallest required fix: Use reliable metrics for the SVG's selected font, or a demonstrably conservative bound for every supported fallback font. Ensure the SVG font selection matches the measurement assumptions.
- Exact regression test required: Render long `W` title/protocol strings, measure the emitted strings independently using the actual selected font metrics, and assert the title is at most 820 units, the protocol is at most 550 units, positioned bounds remain inside the viewport, and truncation markers are present. The test must not use `_measure_svg_text_width` as its oracle.
