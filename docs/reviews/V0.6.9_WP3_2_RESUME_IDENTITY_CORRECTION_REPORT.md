## Root Cause Analysis

### 1. Blocker: Legacy Cursor Binding to Changed Query
- **Defect**: In WP3.1, `CrossrefProvider.search_with_raw` inferred plan pinning whenever `search_run.rendered_query` contained `" || "`. In `FetchAllSearchService`, `rendered_query` was populated with the newly rendered query string when `candidate_queries` was absent or malformed in checkpoint metadata. Consequently:
  - An unpinned legacy two-element cursor (`[query_index, physical_cursor]`) was bound to the newly rendered multi-query plan at `query_index`, issuing an HTTP request with an unverified query.
  - An unpinned single-query raw cursor was accepted without proving query identity.
- **Resolution**:
  - Refactored `search_with_raw` and `FetchAllSearchService._execute_provider` to require explicit structured candidate queries for any in-flight physical cursor.
  - Removed all inference of pinning from `rendered_query`.
  - For legacy cursors (2-element plan cursor or raw physical cursor), `is_pinned` must be true (structured candidate queries must be supplied from checkpoint metadata); otherwise `IncompatibleCrossrefPlanError` is raised before any HTTP request.

### 2. Blocker: Ambiguous Plan Fingerprint Serialization
- **Defect**: Fingerprint computation used `"\n".join(candidate_queries)`. Because terms can contain newlines, distinct candidate query lists such as `["a\nb", "c"]` and `["a", "b\nc"]` produced identical serialized strings (`"a\nb\nc"`) and the same SHA-256 fingerprint (`ea7fb08b7a2dc461`). A versioned cursor created for one plan was incorrectly accepted for the other.
- **Resolution**:
  - Replaced delimiter joining with canonical JSON array serialization:
    `json.dumps(list(candidate_queries), ensure_ascii=False, separators=(",", ":")).encode("utf-8")`.
  - Hashed with SHA-256 (first 16 hex characters).
  - Demonstrably injective: `compute_plan_fingerprint(["a\nb", "c"])` (`869e4af18a4b82a0`) != `compute_plan_fingerprint(["a", "b\nc"])` (`ba97b7d634f69347`).

### 3. Major: Removal of `" || "` Delimiter Parsing
- **Defect**: `CrossrefProvider.search_with_raw` performed `candidate_queries = search_run.rendered_query.split(" || ")`. If a query contained literal `" || "` (e.g. `alpha || beta`), it was split into `["alpha", "beta"]`, truncating the physical query issued to Crossref (`"alpha`).
- **Resolution**:
  - Completely eliminated `search_run.rendered_query.split(" || ")` from `CrossrefProvider`.
  - `rendered_query` is retained strictly as human-readable display metadata and is never parsed as a machine source of truth.
  - Structured `candidate_queries` is passed directly through service and provider boundaries.

### 4. Major Gate Gap: Missing Integration Scenarios
- **Defect**: Independent end-to-end integration tests were absent for (1) the 7x6x4 balanced plan verifying exact physical requests and WP2-compatible provenance fields, and (2) the balanced six-query resume verifying zero position replay.
- **Resolution**:
  - Added permanent integration tests `test_integration_7x6x4_plan_exact_physical_requests_and_provenance` and `test_integration_balanced_six_query_resume_no_replayed_positions`.

## Structured Plan Design & Provenance

```
Checkpoints / Service Layer
┌─────────────────────────────────────────────────────────┐
│ SearchRunCheckpoint.plan_metadata:                      │
│ - candidate_queries: list[str] (saved physical queries) │
│ - plan_fingerprint: str (16-char hex)                   │
│ - planner_version: str ("v0.6.9-wp3")                   │
└─────────────────────────────────────────────────────────┘
                            │
                            ▼ Passed via search_kwargs
┌─────────────────────────────────────────────────────────┐
│ CrossrefProvider.search_with_raw(                       │
│     candidate_queries=...,                              │
│     plan_fingerprint=...,                               │
│     planner_version=...,                                │
│     cursor=...                                          │
│ )                                                       │
└─────────────────────────────────────────────────────────┘
```

1. **Structured Inputs**: `search_with_raw` explicitly accepts `candidate_queries`, `plan_fingerprint`, and `planner_version`.
2. **Validation**:
   - `candidate_queries`: Must be a non-empty sequence of non-empty strings.
   - `plan_fingerprint`: If provided, must match `compute_plan_fingerprint(candidate_queries)`.
   - `cursor`: Decoded into `(query_index, physical_cursor, cursor_fingerprint)`.
3. **In-Flight Resumed Physical Cursor Verification**:
   - Cursor index out-of-bounds (`query_index >= len(candidate_queries)`): raises `IncompatibleCrossrefPlanError` before HTTP.
   - Versioned cursor (`cursor_fingerprint` present): `cursor_fingerprint` must match `compute_plan_fingerprint(candidate_queries)`.
   - Legacy two-element cursor (`cursor.startswith("crossref-plan:")` and no fingerprint): requires `candidate_queries` pinned from checkpoint; issues `candidate_queries[query_index]`.
   - Legacy physical cursor (raw string): requires `candidate_queries` pinned from checkpoint with `len(candidate_queries) == 1`; issues `candidate_queries[0]`.

## Backward Compatibility Policy

| Scenario | In-Flight Cursor | Behavior | Rationale |
|---|---|---|---|
| Checkpoint without physical cursor (`cursor in (None, "*")`) | No | Constructs new plan from `job.query` using current renderer. | No state is in flight; safe to adopt improved planner. |
| Checkpoint with valid saved `candidate_queries` + legacy cursor | Yes | Resumes exact query at `candidate_queries[query_index]`. | Query identity is proven by durable checkpoint metadata. |
| Checkpoint with in-flight cursor + missing/malformed `candidate_queries` | Yes | Raises `IncompatibleCrossrefPlanError` before HTTP; marks checkpoint `failed`, `resumable=False`. | Query identity cannot be proven; guessing would risk issuing wrong requests. |
| Versioned cursor + matching active plan | Yes | Resumes exact query at `candidate_queries[query_index]`. | Query identity is proven by cryptographic SHA-256 fingerprint. |
| Versioned cursor + fingerprint mismatch | Yes | Raises `IncompatibleCrossrefPlanError` before HTTP. | Protects against plan drift across query versions or edits. |
