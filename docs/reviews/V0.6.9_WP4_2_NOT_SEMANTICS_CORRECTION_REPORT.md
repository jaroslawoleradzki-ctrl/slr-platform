## Defect reproduction (independent counterexample)

Direct classifier before fix:

- `AND(Alpha, Gamma, NOT(Beta))` via `classify_candidate` yielded **3** positive groups (expected **2**).
- Pure `NOT(Beta)` via `classify_candidate` yielded **1** positive group (expected **0**).
- Corrected canonical definition `app/domain/crossref_diagnostics.py:group_evidence_for` already yielded **2** and **0** respectively.

Root cause: `app/services/uncertainty_experiment.py:_positive_groups` returned every top-level
AND child verbatim, including `BooleanOperator.NOT` exclusions, and wrapped a pure NOT
expression as a single positive group.

## Fix

File: `app/services/uncertainty_experiment.py`

- Added local `_is_exclusion` predicate mirroring the canonical definition in
  `app/domain/crossref_diagnostics.py` (no WP2 persistence/validation logic duplicated,
  no new production dependency; validator reuse unchanged).
- `_positive_groups` now:
  - filters top-level `NOT` children out of a top-level `AND`;
  - returns `[]` for a pure `NOT` expression;
  - otherwise returns the single expression unchanged (normal positive AND, OR, term,
    and nested-NOT shapes keep canonical single-group semantics).
- `classify_candidate` is otherwise unchanged: real `validate_canonical_query` status,
  per-positive-group `evaluate_expression`, evidenced counting, missing-field aggregation,
  `execution_eligible` passthrough, and tier/policy behavior are untouched.
- WP2 replay adapter path (`app/services/uncertainty_replay_adapter.py`) was not modified;
  existing adapter NOT/pure-NOT tests continue to pass without duplication.
