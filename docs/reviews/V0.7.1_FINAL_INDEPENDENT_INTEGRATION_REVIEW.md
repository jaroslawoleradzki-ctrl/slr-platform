### Semantic Conflict Identified & Resolved (Integration-Only Fix)

**Defect**: During physical reconciliation in [`app/services/production_reconciliation_service.py`](file:///home/cloud/dev/slr-platform-v071-final-integration/app/services/production_reconciliation_service.py), WP4 previously executed:
```sql
UPDATE project_publications SET superseded_by = NULL WHERE project_id = ?
```
**Root Cause**: This blanket reset cleared the `superseded_by` pointer for *all* publications in the project, including legitimate duplicate merges between active records. Consequently:
1. WP3 PRISMA reporting post-reconciliation erroneously counted merged duplicate records as canonical (`records_after_technical_merger` jumped from 11 back to 12).
2. WP2 `reconcile_with_active_corpus` inspected the active duplicate merges, saw `superseded_by` was NULL, misclassified them as inconsistent/tainted, and deleted them from `duplicate_group_merges`.

**Resolution**: Updated the query in [`app/services/production_reconciliation_service.py`](file:///home/cloud/dev/slr-platform-v071-final-integration/app/services/production_reconciliation_service.py) to target only references pointing to the allow-listed records being removed:
```python
conn.execute(
    "UPDATE project_publications SET superseded_by = NULL WHERE project_id = ? AND superseded_by IN (%s)"
    % ",".join("?" * len(request.record_ids)),
    (request.project_id, *(str(i) for i in request.record_ids)),
)
```
This preserves referential integrity if an active record pointed to a deleted record, while preserving all legitimate active-to-active duplicate merges.
