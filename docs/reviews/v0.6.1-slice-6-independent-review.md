## P1 findings

### P1-S6-1 — Formula protection does not cover dynamic CSV/XLSX headers

- Severity: P1
- Exact file/function/document:
  - `app/services/export/xlsx_workbook.py`, `_write_header`
  - `app/services/extraction_dataset_service.py`, `ExtractionDatasetService.export_csv`
- Concrete evidence: `_write_header()` directly appends strings without `excel_safe_cell()`. An adversarial QA question produced an XLSX header beginning `=HYPERLINK(...)`; openpyxl classified the resulting cell as formula type `f`. CSV similarly writes dynamic `_value_headers()` without `sanitize_csv_cell()`.
- Actual behavior: Persisted QA questions or extraction field keys beginning with formula-trigger characters can become executable spreadsheet formulas in header cells.
- Required behavior: Every string cell, including dynamically generated headers, must use the format's formula guard.
- Consequence: Opening an exported CSV/XLSX workbook can execute attacker-controlled spreadsheet formulas.
- Smallest required fix: Sanitize every CSV header with `sanitize_csv_cell()` and every XLSX header with `excel_safe_cell()` before writing.
- Exact regression test required: Create an extraction field key and QA criterion question beginning with `=HYPERLINK(...)`, export CSV/XLSX, and assert CSV headers begin with `'=`, while openpyxl reports XLSX header cells as text rather than `data_type == "f"`.

### P1-S6-4 — Character-count clamping does not guarantee readable PRISMA metadata

- Severity: P1
- Exact file/function/document:
  - `app/services/export/prisma_svg_renderer.py`, `render_prisma_svg`
  - `app/services/export/prisma_pdf_renderer.py`, `render_prisma_pdf`
- Concrete evidence:
  - Both renderers truncate titles at 100 characters without measuring rendered width.
  - The shared canvas is 860 points wide with about 820 points available after margins.
  - In the bundled PDF font, 100 `W` characters at the configured size measure 840.65 points before adding protocol text.
  - SVG additionally prepends `PRISMA 2020 Flow Diagram —`, making overflow substantially larger.
  - Protocol version remains unbounded.
  - Tests assert only XML parsing or PDF magic/size, not readability or bounds.
- Actual behavior: Valid long or wide metadata can be clipped, overlap protocol metadata, or extend outside the printable viewport.
- Required behavior: Long metadata must remain readable through width-aware truncation or deterministic wrapping without altering the underlying flow model.
- Consequence: Required project/protocol identification can be unreadable in publication artifacts.
- Smallest required fix: Implement deterministic width-aware fitting/wrapping for title and protocol text, reserving separate non-overlapping regions in both renderers.
- Exact regression test required: Render wide-glyph titles and long protocol values; assert every SVG/PDF text line remains within its allocated width, includes an explicit truncation marker where needed, parses successfully, and preserves identical counts/stage semantics across SVG and PDF.
