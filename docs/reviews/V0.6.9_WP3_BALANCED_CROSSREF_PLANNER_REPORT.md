## Original defect
In v0.6.8 / v0.6.9 WP1, candidate queries for an AND node with child plans $P_0, P_1, \dots, P_{K-1}$ (lengths $L_0, L_1, \dots, L_{K-1}$, total Cartesian space $N = \prod_{j=0}^{K-1} L_j$) were sampled using a 1-D mixed-radix rank selection bounded to $B = \text{MAX\_CROSSREF\_CANDIDATE\_QUERIES} = 6$:
$$\text{rank}_i = \left\lfloor \frac{i \cdot N}{B} \right\rfloor \quad \text{for } i \in \{0, 1, \dots, B-1\}$$

In mixed-radix decomposition, digits were unrolled from the last axis ($j = K-1$) to the first ($j = 0$):
$$\text{index}_{K-1} = \text{rank} \pmod{L_{K-1}}$$
$$\text{index}_{K-2} = (\text{rank} // L_{K-1}) \pmod{L_{K-2}}$$

For the diagnosed canonical Lean/Energy strategy, group lengths were:
- Axis 0 (Lean): $L_0 = 7$
- Axis 1 (Energy): $L_1 = 6$
- Axis 2 (Manufacturing): $L_2 = 4$
- Total combinations: $N = 7 \times 6 \times 4 = 168$

Because $B = 6$ divides $L_1 = 6$, the stride $S = N / B = (7 \times 6 \times 4) / 6 = 28$ was an exact integer.
Crucially, $S = 28 = 7 \times 4$ is an exact multiple of $L_2 = 4$.
Consequently:
$$\text{rank}_i \pmod{L_2} = (i \cdot 28) \pmod 4 \equiv 0 \quad \text{for all } i \in \{0, 1, 2, 3, 4, 5\}$$

This arithmetic resonance between the rank stride ($28$) and the final radix ($4$) collapsed the lowest-order axis to index 0 across all 6 queries. Every single physical query received `"Manufacturing"`, while `"Production"`, `"Industrial"`, and `"Factory"` received 0 representation.

## Architecture investigation
Crossref has no Boolean tree API; multi-term expressions are executed as quoted candidate anchor strings through the free-text `query` parameter.
Candidate queries are planned during query rendering (`app/rendering/crossref.py`).
The provider (`app/providers/search/crossref.py`) sequentially executes each physical candidate query using cursor-based pagination.
The resume mechanism encodes state as `crossref-plan:<base64([query_index, physical_cursor])>`, relying on a strictly deterministic, reproducible query sequence across process restarts.

## Algorithm considered
1. **Coprime rank strides / modular rank shifting**:
   Adding offsets or using coprime rank strides still operates in 1-D rank projection. When factors of radices align, 1-D projections can create uneven clustering or fail to guarantee complete coverage across arbitrary combinations of axes.
2. **Independent round-robin with phase shifts**:
   Selecting coordinates independently along each axis using periodic round-robin (`(i + offset_j) % L_j`) fails when all axis lengths are small (e.g., $2 \times 2 \times 2 = 8 > 6$). In such cases, functions with period 2 repeat at step 2 and step 4, causing unavoidable duplicate queries.
3. **Stratified deterministic greedy covering selection (Selected)**:
   Stratifies large axes to $B$ evenly spaced representative candidate alternatives, and deterministically allocates queries to maximize new alternative coverage across all axes (primary objective), penalize over-used alternatives (secondary), and maximize pair-wise diversity (tertiary).

## Selected algorithm
The chosen algorithm is **Stratified Deterministic Greedy Covering Selection**:
1. If the Cartesian product $N \le B = 6$, the exact full Cartesian product is emitted in canonical order (`itertools.product`), preserving all combinations without sampling.
2. If $N > B$:
   - For each axis $j$, if $L_j \le B$, all $L_j$ alternatives are candidates.
   - If $L_j > B$, $B$ candidate indices are selected using exact integer spanning:
     $$\text{idx}_i = \left\lfloor \frac{2 \cdot i \cdot (L_j - 1) + (B - 1)}{2 \cdot (B - 1)} \right\rfloor \quad \text{for } i \in \{0, \dots, B-1\}$$
     This guarantees strictly increasing, evenly spaced indices spanning from alternative $0$ to alternative $L_j - 1$.
   - The planner iteratively selects $B$ unique tuples:
     - Primary weight ($+10,000$): unrepresented alternatives on any axis.
     - Usage penalty ($-100 \times \text{usage}$): balances repetition when $L_j < B$.
     - Diversity bonus ($+10$): unrepresented pairwise combinations across axes.
     - Deterministic tie-breaking: canonical lexicographical ordering.
   - For combinatorial spaces where the candidate product exceeds 10,000 (e.g. 6+ AND groups with many synonyms), a coordinate-wise greedy selection with deterministic perturbation fallback is used, providing $O(B \cdot K)$ runtime.

This design was selected because it is mathematically proven to eliminate axis collapse, guarantees zero duplicates, preserves full product when $N \le 6$, and is fully generic for arbitrary queries.

## Algorithm invariants
- **Bound**: Never generates more than $\min(6, N)$ physical queries.
- **Determinism**: Purely deterministic functions with stable integer tie-breaking; no randomness.
- **Uniqueness**: Every generated physical query in the bounded plan is distinct.
- **Full-product preservation**: If $N \le 6$, all combinations are preserved in Cartesian order.
- **Balanced axis coverage**: For every axis $j$, the number of distinct alternatives represented is $\min(B, L_j)$. When $L_j < B$, repetitions are distributed with at most difference 1 in frequency.
- **Stable ordering**: Queries are deterministically ordered and stable for cursor/query-index resume.

## Plan metadata
The `RenderedQuery.metadata` dictionary for Crossref now includes detailed per-axis audit information:
- `possible_candidate_combinations`: total logical product combinations ($N$)
- `planned_candidate_combinations`: number of physical queries in the bounded plan
- `physical_query_bound`: maximum allowed queries ($6$)
- `axis_coverage`: list of per-axis coverage entries:
  - `axis_index`: 0-indexed axis position
  - `group_index`: 0-indexed group position (alias)
  - `available_alternatives`: total alternatives available in that concept group
  - `represented_alternatives`: distinct alternatives included in the bounded plan
  - `coverage_ratio`: ratio of represented / available
- `min_axis_coverage_ratio`: the minimum coverage ratio across all axes (e.g. $0.8571$ for the diagnosed case)
